# Development Journal — Manual Attack Direction & Attack Animator

**Time Spent:** ~4 hours

## Overview

Today I continued working on the player combat system.

The main focus was creating a manual attack direction system controlled by the mouse and connecting the selected attack angle with the player's attack animation.

The goal was to allow the player to freely choose an attack direction instead of using a fixed number of attack directions.

## What I Implemented

### PlayerAttackDirection

I created and developed a new `PlayerAttackDirection.cs` component.

The component is responsible for selecting the player's attack direction before the attack is performed.

The selected direction is exposed through:

```text
AttackDirection
AttackAngle
```

### Manual Attack Direction

I implemented a virtual mouse position for selecting the attack direction.

While the player is holding ALT, the script reads the mouse movement using:

```text
Mouse.current.delta
```

The mouse movement is accumulated into a virtual position that represents the direction selected by the player.

The virtual position is reset every time the player starts a new direction selection.

This means that every attack can start with a fresh direction instead of continuing from the direction of the previous attack.

### 360° Attack Direction

The attack direction is not limited to a fixed number of directions.

The virtual mouse position is converted into an angle using:

```text
Mathf.Atan2()
```

The current system uses:

```text
0°   = Up
90°  = Right
180° = Down
-90° = Left
```

This allows the player to select intermediate angles as well.

### PlayerCombat Integration

I connected the selected attack angle with `PlayerCombat`.

When the player attacks, `PlayerCombat` retrieves the current value from:

```text
PlayerAttackDirection.AttackAngle
```

The angle is then passed to the Animator using:

```text
animator.SetFloat("AttackAngle", attackAngle);
```

The attack direction is also passed to `PlayerAttackController`, which is responsible for setting the weapon's direction in the world.

### Attack Animator Blend Tree

I connected the attack animations to an Animator Blend Tree using the `AttackAngle` parameter.

The current reference points in the Blend Tree are:

```text
-90 = Left
  0 = Top
 90 = Right
```

The purpose of these points is to allow the Blend Tree to interpolate between the available attack animations while the player can select intermediate angles.

## Problems I Encountered

### Attack Direction Was Accumulating

The first approach used the mouse delta to continuously add to the previous attack angle.

This caused the next attack direction to depend on the previous attack.

I changed the system so that the virtual mouse position is reset whenever the player starts holding ALT.

This allows every new attack direction selection to start independently.

### Attack Angle Did Not Match The Animator

At one point, an attack with an `AttackAngle` of `90°` did not correctly select the right-side animation.

The problem was related to recalculating the angle inside `PlayerCombat` instead of using the already calculated `AttackAngle`.

I changed `PlayerCombat` to use the value directly from `PlayerAttackDirection`.

After this correction, the attack direction and Animator parameter were much more consistent.
